1.1 ~65 min

⌨️ The /inema language

From the first slash to the full runtime: how a command declares work, receives parameters, and combines into chains.

What it is:

A short DSL for controlling how models and agents research, verify, decide, and execute. Each command carries a work protocol.

Why learn:

Without a language, you reuse scattered prompts. With one, the same request produces standardized, verifiable output.

Key concepts:

DSL · declarative command · protocol · reproducibility.

What it is:

Slash + short name, with optional parameters in key=value format: /rank criteria=impact,cost,risk.

Why learn:

Syntax is the only mechanism you need to memorize—everything else is command vocabulary.

Key concepts:

prefix / · key=value parameter · space-separated composition.

What it is:

The official rules: commands are declarative instructions; order matters in an explicit chain; in a conflict, the more specific rule takes precedence, then the more recent one.

Why learn:

It’s what prevents unpredictable behavior when two requests collide.

Key concepts:

declarativeness · specific > recent precedence · runtime records everything.

What it is:

Several commands on the same line form a bundle of instructions executed together.

Why learn:

The composition covers 80% of daily use without needing an explicit /chain.

Key concepts:

instruction package · synergy between families · parsimony.

What it is:

/chain(/research -> /truth -> /rank -> /decide) sets the order and passes the relevant output from one command to the next.

Why learn:

Chains produce repeatable workflows—the foundation for the presets in module 6.2.

Key concepts:

explicit order · output handoff · pipeline.

What it is:

/mode activates a persistent behavior profile (conservative, exploratory, executive). /preset expands a short name into a predefined chain.

Why learn:

They’re the highest-level controls: they change the “how” of everything that follows.

Key concepts:

global profile · macro expansion · consistency across sessions.

What it is:

Every command can have acceptance criteria and a fallback; the runtime logs inputs, outputs, tools used, confidence, and failures.

Why learn:

It’s what makes the language auditable — you know what ran, how confident it was, and what to do when it fails.

Key concepts:

operational log · stated confidence · safe fallback.

🔍 Truth and verification

The 10 commands in family 01: from /truth to /freshness — the antidote to hallucinations and false certainty.

What it is:

Separates verified facts, inferences, hypotheses, and unknowns; reports confidence levels.

Why learn:

It’s the language’s most commonly used command — the basic hygiene for any response.

Key concepts:

fact vs. inference · verified assumption · stated confidence.

What it is:

/verify looks for enough evidence to confirm, correct, or reject a specific claim; /evidence shows which proof supports each conclusion.

Why learn:

Turn "trust me" into "check for yourself".

Key concepts:

target claim · evidentiary basis · data gap.

What it is:

Organizes sources by authority, recency, proximity to the facts, and independence.

Why learn:

Three independent sources are worth more than ten citing the same origin.

Key concepts:

source hierarchy · dependency between citations.

What it is:

Breaks content into verifiable claims and classifies each as confirmed, inaccurate, false, inconclusive, or opinion.

Why learn:

It’s the standard audit before publishing or making a decision based on a text.

Key concepts:

verifiable claim · verdict taxonomy.

What it is:

Assigns a confidence level to conclusions and explains which factors would increase or decrease that confidence.

Why learn:

Good decisions use calibrated confidence, not a confident tone.

Key concepts:

calibration · conclusion sensitivity.

What it is:

/uncertainty surfaces missing data and plausible interpretations; /assumptions lists premises marked as verified, reasonable, or weak.

Why learn:

An unstated weak assumption is the #1 cause of polished but incorrect analysis.

Key concepts:

uncertainty inventory · assumption status.

What it is:

Show where each critical piece of information came from: primary data, secondary data, inference, or user-provided.

Why learn:

Distinguishes “I measured it” from “someone told me”—and that changes how much weight the evidence carries.

Key concepts:

chain of custody for information.

What it is:

/freshness identifies what may have changed and requires an update before using time-sensitive data. It closes the module with the complete audit workflow.

Why learn:

Presenting an outdated statistic as current is the easiest mistake to make—and to catch with the right command.

Key concepts:

time validity · update trigger · layered auditing.
